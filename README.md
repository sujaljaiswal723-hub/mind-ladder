# Mind Ladder — Netlify project

## Deployment limitation — read first

This is a complete, built and tested Netlify Functions + Blobs project. **It cannot deploy its multiplayer function through Netlify's browser drag-and-drop uploader.** Netlify Drop uploads static files; it does not build or deploy server functions. Putting source, a function ZIP, or netlify.toml in the uploaded folder does not change this.

Netlify must deploy the function through a supported function-aware build/deploy integration. This archive does not require GitHub specifically. It contains everything a supported deploy integration needs, including prebuilt frontend assets and a packaged function. No such deployment has been performed here. No terminal instructions, application secrets, API keys, environment variables, or database setup are required by the application itself. Netlify supplies the Blobs connection to its deployed function automatically.

Official references:
- https://docs.netlify.com/deploy/create-deploys/
- https://answers.netlify.com/t/all-functions-get-a-404-error/124134
- https://docs.netlify.com/build/data-and-storage/netlify-blobs/

## Behavior preserved

2–8 players join by a six-character room code. Nine rounds advance from easy to medium to hard. Each round lasts 45 seconds with one answer per player. Correct answers score 100/200/300 points; a hint halves that round's points. Missing or incorrect answers score zero. Answers stay hidden until the round ends. The host advances rounds, highest score wins, and ties share the win. Rematches use the same puzzles. Polling remains every 900 ms; there is no continuously running production backend.

The frontend calls `/.netlify/functions/game` directly for all room actions and polling. There is no custom function path, API redirect, SQL database, Cloudflare dependency, persistent server process, or separate storage setup.

## Concurrency and storage

The standard Netlify function opens `mind-ladder-rooms` with strong consistency. Creation uses `onlyIfNew: true`; every update uses the ETag read by `getWithMetadata` with `onlyIfMatch`. Conflicts reread the room and retry up to eight times. A missing ETag fails closed rather than performing an unconditional write. Room data persists in Netlify Blobs between invocations and deploys.

## Build implementation

The frontend uses a portable in-process WebAssembly compiler to avoid requiring native build binaries. Netlify's ordinary build processes the standard TypeScript function entry. Prepackaging uses the same function source plus Netlify's official packaging library. No puzzle answers or backend SDK are shipped in the frontend bundle.
